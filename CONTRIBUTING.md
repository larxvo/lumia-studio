# Contributing

Thank you for helping improve Luma Studio. Start with [development setup](docs/DEVELOPMENT.md), [architecture](docs/ARCHITECTURE.md) and the [compatibility matrix](docs/COMPATIBILITY.md).

For a bug report, include the version, OS, reproduction steps, expected/actual behavior and whether it occurs in Windows or the browser. Share a minimal non-sensitive fixture only if you have permission to publish it. Never attach private documents, faces, tokens or client secrets without appropriate consent.

Keep pull requests focused. Describe the concrete problem and resulting behavior, the relevant validation, and any compatibility/quality limits. Preserve `.luma` migration behavior, original-source retention, mask protection, cancellation and undo. Run checks appropriate to the change; report actual results rather than describing mocks as live service/GPU validation.

Application code is MIT. Keep existing author attribution and third-party licenses. New model/assets need clear provenance, redistributable licensing, hashes and preprocessing notes. Do not add paid API keys, telemetry, forced watermarks or a paywall to the default experience.

Feature requests should describe a user task and a reviewable acceptance criterion, such as preserving hair strands or importing a specific PSD structure. Discuss format-engine changes and new external services before introducing substantial dependencies.
